# 戦略仕様

EA は単一プロセスで 1 つの戦略のみ動かす。`InpStrategy` 入力で切り替える。同時運用は検証性を損なうため禁止。

---

## A) `EMA13_PULLBACK` — EMA13 パターン手法

### 出典

X 投稿 (@Kirto_JPY) より着想:
> エントリー条件
> ・100EMA が右肩上がりであること
> ・13EMA にタッチでエントリー
> 否定したらすぐ損切り

### 機械化ルール (このEAでの実装)

| 項目 | 仕様 |
|------|------|
| デフォルト時間足 | M5 |
| トレンドフィルタ | 100EMA の傾きが正 (`EMA100[0] > EMA100[InpTrendSlopeBars]`、デフォルト10本前) → ロング許可。負傾き → ショート許可。傾き不在 → ノートレード |
| エントリ (買) | 上昇トレンド中、ローソクの安値が 13EMA を **タッチまたは下抜け、かつ終値が 13EMA を上回って確定** したバーで成行買い |
| エントリ (売) | 下降トレンド中、ローソクの高値が 13EMA を **タッチまたは上抜け、かつ終値が 13EMA を下回って確定** したバーで成行売り |
| ストップロス | エントリ時 ATR(14) × `InpATR_SL_Mult` (デフォルト 1.5) |
| 利確 | SL 距離 × `InpRR` (デフォルト 1.5R)。トレーリングは行わない (シンプルさ優先) |
| 「否定したらすぐ損切り」の解釈 | EMA13 を逆方向に終値ベースでクリアしたら市場決済 (元の SL より早期に切る安全装置) |
| エントリ抑制 | 直近 N=`InpCooldownBars` 本以内に同方向の取引があった場合スキップ (連打防止) |

### 設計上の懸念事項 (検証で確認すること)

- 「EMAタッチ」の定義が曖昧 → 「ヒゲでのタッチ」と「終値でのタッチ」で挙動が大きく変わる。本実装は **ヒゲタッチ + 終値で逆側に戻る** を採用するが、要パラメータ実験
- M5 ではスプレッドコストが効きやすい。XAUUSD のスプレッドは平時 30-50 cents、指標時は 100+ cents → 利確 1.5R が薄利すぎる可能性
- 100EMA の傾き判定は離散的 → トレンド転換期に頻繁に方向が反転する可能性

### 反証条件 (この戦略を「不採用」とする基準)

下記すべてを満たした場合は採用を見送り、`docs/strategy.md` に「不採用」と追記する:
- アウトオブサンプル (2022-2024) の Profit Factor < 1.0
- または Max Drawdown > 25%
- または取引数 < 30 (検証不能)

## B) `EMA20_M10` — 10分足 × 20EMA 手法

### 出典

X 投稿 (@Kirto_JPY) より着想:
> 「10分足×20EMA」
> 中間足である10分足と20EMAの相性が凄すぎます
> 35回の検証:28回勝ち、7回負け、勝率78.4%

**統計的注記**: N=35 はランダム手法でも珍しくない結果。真の勝率 50% の戦略でも、35 試行中 28 勝以上となる確率は二項分布で約 0.5%、決して0%ではない。500試行以上で再検証する必要がある。

### 機械化ルール

| 項目 | 仕様 |
|------|------|
| デフォルト時間足 | M10 (MT5 ネイティブ対応) |
| トレンドフィルタ | 20EMA の傾き (`EMA20[0] > EMA20[InpSlopeBars]`、デフォルト 5 本前)。または上位足 H1 の 50EMA 傾き (`InpUseHTFFilter=true` で有効) |
| エントリ (買) | 上昇トレンド、価格が 20EMA を上から触り、再び終値で 20EMA 上に戻ったバーで成行買い |
| エントリ (売) | 下降トレンド、価格が 20EMA を下から触り、再び終値で 20EMA 下に戻ったバーで成行売り |
| ストップロス | ATR(14) × `InpATR_SL_Mult` (デフォルト 1.5)、または直近スイング (高値/安値) — `InpStopMode` で切替 |
| 利確 | SL × `InpRR` (デフォルト 1.5R) |
| クールダウン | 直近 N=`InpCooldownBars` (デフォルト 3) 本以内のエントリは抑制 |

### 設計上の懸念事項

- M10 は流動性が薄い時間帯にノイズが多い → セッションフィルタとの組み合わせ必須
- 「20EMAタッチからの反発」は事後的には明瞭だが、リアルタイムでは **「タッチして抜けて戻る」と「タッチして抜けたまま」の判別** が難しい → 1〜2本の確定待ちを要する → 実質エントリ価格は EMA からやや離れる

### 反証条件

A) と同じ。

## C) `DONCHIAN_BREAK` — 比較ベースライン (古典手法)

### 概要

機械化が完全で過剰最適化が起きにくい古典ブレイクアウト。EMA 系2つの結果を **「単に古典より良いか?」** という観点で評価するためのベースライン。

| 項目 | 仕様 |
|------|------|
| デフォルト時間足 | H1 |
| エントリ (買) | 直近 N=20 本の高値ブレイクで成行買い |
| エントリ (売) | 直近 N=20 本の安値ブレイクで成行売り |
| ストップロス | ATR(14) × 2.0 |
| 利確 | トレーリングストップ ATR × 3.0、または反対側 Donchian (10本) 到達で決済 |

## 共通ロジック (全戦略)

### ポジションサイジング

```
risk_amount = AccountBalance × InpRiskPercent / 100
sl_distance_in_points = SL価格 と エントリ価格の差 / Point
tick_value = SymbolInfoDouble(Symbol, SYMBOL_TRADE_TICK_VALUE)
lot = risk_amount / (sl_distance_in_points × tick_value)
lot = NormalizeLotToBrokerStep(lot)  // ブローカーの最小ロット/ステップに合わせる
```

### 日次ドローダウン回路ブレーカー

- 当日の累積損失が `InpMaxDailyLossPct`% を超えたら、その日いっぱい新規エントリ停止
- 翌日 00:00 UTC でリセット

### セッションフィルタ

- デフォルトで London-NY オーバーラップ重視 (UTC 08:00 - 21:00)
- 金曜は `InpFridayCloseHourUTC` (デフォルト 20:00 UTC) で全ポジション強制決済

### 同時保有制限

- 1 ポジションのみ。新規シグナルは既存ポジションがあればスキップ

### 同方向連続エントリ抑制

- `InpCooldownBars` 本以内の同方向連打を抑制 (デフォルト 3)
