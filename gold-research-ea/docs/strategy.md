# 戦略仕様

EA は単一プロセスで 1 つの戦略のみ動かす。`InpStrategy` 入力で切り替える。同時運用は検証性を損なうため禁止。

## 戦略一覧

| ID | 名称 | デフォルトTF | SL/TPデフォルト |
|----|------|------------|----------------|
| `EMA13_PULLBACK` | EMA13プルバック + 早期撤退 | M5 | ATR |
| `EMA20_M10` | 10分足 × 20EMA | M10 | ATR |
| `SMA_CROSS_M15` | SMA5/SMA20 クロス | M15 | PIPS |
| `EMA20_M15_8BAR` | EMA20クロス + 確認足 | M15 | SWING |
| `DONCHIAN_BREAK` | 古典ブレイクアウト (比較用) | H1 | ATR |

## SL/TPモード共通仕様 (`InpStopMode`)

| モード | 仕様 |
|-------|------|
| `STOP_ATR` | SL = エントリ ± ATR(14) × `InpATR_SL_Mult`、TP = SL距離 × `InpRR` |
| `STOP_PIPS` | SL = `InpSL_Pips` × `InpPipSize`、TP = `InpTP_Pips` × `InpPipSize` (または `InpPips_UseRR=true` なら `SL_Pips × RR`) |
| `STOP_SWING` | SL = 直近 `InpSwingLookback` バーの安値 (買) / 高値 (売)、TP = 反対側の極値 |

XAUUSDの `InpPipSize` はブローカーによって `0.1` (1pip=10points, digits=2) が一般的。`0.01` (digits=2 で 1pip=1point) で扱うブローカーも稀にあるため、デモで確認してから変更すること。

## A) `EMA13_PULLBACK` — EMA13 パターン手法

### 出典

X 投稿 (@Kirto_JPY) より着想:
> エントリー条件
> ・100EMA が右肩上がりであること
> ・13EMA にタッチでエントリー
> 否定したらすぐ損切り

### 機械化ルール (このEAでの実装)

| 項目 | 仕様 |
|------|------|
| デフォルト時間足 | M5 |
| トレンドフィルタ | 100EMA の傾きが正 (`EMA100[0] > EMA100[InpTrendSlopeBars]`、デフォルト10本前) → ロング許可。負傾き → ショート許可。傾き不在 → ノートレード |
| エントリ (買) | 上昇トレンド中、ローソクの安値が 13EMA を **タッチまたは下抜け、かつ終値が 13EMA を上回って確定** したバーで成行買い |
| エントリ (売) | 下降トレンド中、ローソクの高値が 13EMA を **タッチまたは上抜け、かつ終値が 13EMA を下回って確定** したバーで成行売り |
| ストップロス | エントリ時 ATR(14) × `InpATR_SL_Mult` (デフォルト 1.5) |
| 利確 | SL 距離 × `InpRR` (デフォルト 1.5R)。トレーリングは行わない (シンプルさ優先) |
| 「否定したらすぐ損切り」の解釈 | EMA13 を逆方向に終値ベースでクリアしたら市場決済 (元の SL より早期に切る安全装置) |
| エントリ抑制 | 直近 N=`InpCooldownBars` 本以内に同方向の取引があった場合スキップ (連打防止) |

### 設計上の懸念事項 (検証で確認すること)

- 「EMAタッチ」の定義が曖昧 → 「ヒゲでのタッチ」と「終値でのタッチ」で挙動が大きく変わる。本実装は **ヒゲタッチ + 終値で逆側に戻る** を採用するが、要パラメータ実験
- M5 ではスプレッドコストが効きやすい。XAUUSD のスプレッドは平時 30-50 cents、指標時は 100+ cents → 利確 1.5R が薄利すぎる可能性
- 100EMA の傾き判定は離散的 → トレンド転換期に頻繁に方向が反転する可能性

### 反証条件 (この戦略を「不採用」とする基準)

下記すべてを満たした場合は採用を見送り、`docs/strategy.md` に「不採用」と追記する:
- アウトオブサンプル (2022-2024) の Profit Factor < 1.0
- または Max Drawdown > 25%
- または取引数 < 30 (検証不能)

## B) `EMA20_M10` — 10分足 × 20EMA 手法

### 出典

X 投稿 (@Kirto_JPY) より着想:
> 「10分足×20EMA」
> 中間足である10分足と20EMAの相性が凄すぎます
> 35回の検証:28回勝ち、7回負け、勝率78.4%

**統計的注記**: N=35 はランダム手法でも珍しくない結果。真の勝率 50% の戦略でも、35 試行中 28 勝以上となる確率は二項分布で約 0.5%、決して0%ではない。500試行以上で再検証する必要がある。

### 機械化ルール

| 項目 | 仕様 |
|------|------|
| デフォルト時間足 | M10 (MT5 ネイティブ対応) |
| トレンドフィルタ | 20EMA の傾き (`EMA20[0] > EMA20[InpSlopeBars]`、デフォルト 5 本前)。または上位足 H1 の 50EMA 傾き (`InpUseHTFFilter=true` で有効) |
| エントリ (買) | 上昇トレンド、価格が 20EMA を上から触り、再び終値で 20EMA 上に戻ったバーで成行買い |
| エントリ (売) | 下降トレンド、価格が 20EMA を下から触り、再び終値で 20EMA 下に戻ったバーで成行売り |
| ストップロス | ATR(14) × `InpATR_SL_Mult` (デフォルト 1.5)、または直近スイング (高値/安値) — `InpStopMode` で切替 |
| 利確 | SL × `InpRR` (デフォルト 1.5R) |
| クールダウン | 直近 N=`InpCooldownBars` (デフォルト 3) 本以内のエントリは抑制 |

### 設計上の懸念事項

- M10 は流動性が薄い時間帯にノイズが多い → セッションフィルタとの組み合わせ必須
- 「20EMAタッチからの反発」は事後的には明瞭だが、リアルタイムでは **「タッチして抜けて戻る」と「タッチして抜けたまま」の判別** が難しい → 1〜2本の確定待ちを要する → 実質エントリ価格は EMA からやや離れる

### 反証条件

A) と同じ。

## C) `SMA_CROSS_M15` — SMA5×SMA20 ゴールデン/デッドクロス

### 出典

X 投稿 (@mzgaangy "月800万超えトレーダー") より着想:
> 時間足: 15分足 / 通貨: XAUUSD
> SMA5(短期) が SMA20(中期) を下から上抜け → ロング
> SMA5 が SMA20 を上から下抜け → ショート
> 利確 30〜40pips または直近高値、損切 20〜30pips または直近安値

末尾はLINE登録誘導 (情報商材アフィリエイトのテンプレート) で締めくくられている。投稿者の収益主張は **独立検証していない**。手法そのものはダブル移動平均クロスとして極めて古典的で、長年にわたって「単独ではほぼ機能しない」と多くの公開研究で示されているもの。検証することに意味はあるが、過信は禁物。

### 機械化ルール

| 項目 | 仕様 |
|------|------|
| デフォルト時間足 | M15 |
| エントリ (買) | 直前バーで SMA5 ≤ SMA20、確定バーで SMA5 > SMA20 |
| エントリ (売) | 直前バーで SMA5 ≥ SMA20、確定バーで SMA5 < SMA20 |
| SL/TP | `InpStopMode` で選択。投稿準拠なら `STOP_PIPS` (SL=25pips, TP=35pips) |

### 既知の課題

- 単純MAクロスは **ホイップソー** (チョッピー相場で連続損切り) に極めて脆弱
- トレンドフィルタなし → レンジ相場で被害が大きい
- 「直近高値で利確 / 直近安値で損切」を厳密に実装したい場合は `InpStopMode=STOP_SWING`

## D) `EMA20_M15_8BAR` — EMA20クロス + N本以内タッチ + 確認足

### 出典

X 投稿 (@Cora641899... "月600万稼ぐプロ") より着想:
> EMA20 × 15分足 × 8つのローソク足
> ① ローソク足がEMA20を下から上に抜けて足が確定
> ② EMA20の上にある状態でEMA20にタッチしたタイミングで
> EMAにタッチした足が「上昇ピンバー」「上昇継続(3種)」のどれかになったことを確認 → 次の足でロング
> 利確: 直近高値 (3分割部分利確推奨) / 損切: 直近安値

投稿の末尾は「極秘マニュアル配布」を餌にした LINE 誘導 (`lin.ee/3H62Ort`)。古典的な情報商材アフィリの集客文体。手法そのものは検証する価値があるが、「月600万」「FX初心者が1ヶ月で50万」などの主張は **独立検証されていない**。

### 機械化ルール

| 項目 | 仕様 |
|------|------|
| デフォルト時間足 | M15 |
| トレンド条件 | 直近 `InpEMA20Cross_Lookback` (デフォルト8) 本以内に EMA20 の上抜けクロスがあり、それ以降のすべての終値が EMA20 を上回っている |
| タッチ条件 | 確定バーの安値 ≤ EMA20、かつ終値 ≥ EMA20 |
| 確認足 (4種のブル/ベアパターンの集約) | 下記いずれか満たせば「ブル確認」: <br> ・**上昇ピンバー**: 下ヒゲ ≥ 実体の `InpEMA20Cross_PinWickRatio` 倍 (デフォルト2.0)、かつ下ヒゲ ≥ 上ヒゲ×1.5、かつ実体が高値圏60%以上 <br> ・**強い終値継続**: 緑足 (close > open)、かつ終値が高値圏 `InpEMA20Cross_StrongClose` (デフォルト 0.7 = 上位30%) 以上 |
| ショート確認 | ブル確認の上下対称 (上ヒゲ長・赤足・終値が安値圏) |
| SL/TP | デフォルト `STOP_SWING` (`InpSwingLookback` バーの直近高値/安値)。投稿のオリジナル仕様に最も近い |

### 8種のローソクパターンの解釈

投稿の画像で示された「上昇ピンバー1種 + 上昇継続3種」「下降ピンバー1種 + 下降継続3種」は、機械的に厳密分類するとパラメータが激増するため、本実装では **「下ヒゲが長く実体が上にあるピンバー」と「終値が高値圏に寄った強い継続足」の2分類** に集約。3種の連続パターンの厳密区別は backtest 上ノイズの方が大きくなるため簡素化した。実装結果が芳しくない場合のみ、パターン定義の精緻化を検討。

### 既知の懸念

- 直近高値/安値が遠すぎるとロット数が極小になりエントリ不可、近すぎると RR が悪化する → `InpSwingLookback` 調整が結果を大きく変える (= 過剰最適化リスク)
- 「3分割部分利確」は本実装では未対応 (全量決済のみ)。実装したい場合は別途トレード管理層が必要

## E) `DONCHIAN_BREAK` — 比較ベースライン (古典手法)

### 概要

機械化が完全で過剰最適化が起きにくい古典ブレイクアウト。EMA 系2つの結果を **「単に古典より良いか?」** という観点で評価するためのベースライン。

| 項目 | 仕様 |
|------|------|
| デフォルト時間足 | H1 |
| エントリ (買) | 直近 N=20 本の高値ブレイクで成行買い |
| エントリ (売) | 直近 N=20 本の安値ブレイクで成行売り |
| ストップロス | ATR(14) × 2.0 |
| 利確 | トレーリングストップ ATR × 3.0、または反対側 Donchian (10本) 到達で決済 |

## 共通ロジック (全戦略)

### ポジションサイジング

```
risk_amount = AccountBalance × InpRiskPercent / 100
sl_distance_in_points = SL価格 と エントリ価格の差 / Point
tick_value = SymbolInfoDouble(Symbol, SYMBOL_TRADE_TICK_VALUE)
lot = risk_amount / (sl_distance_in_points × tick_value)
lot = NormalizeLotToBrokerStep(lot)  // ブローカーの最小ロット/ステップに合わせる
```

### 日次ドローダウン回路ブレーカー

- 当日の累積損失が `InpMaxDailyLossPct`% を超えたら、その日いっぱい新規エントリ停止
- 翌日 00:00 UTC でリセット

### セッションフィルタ

- デフォルトで London-NY オーバーラップ重視 (UTC 08:00 - 21:00)
- 金曜は `InpFridayCloseHourUTC` (デフォルト 20:00 UTC) で全ポジション強制決済

### 同時保有制限

- 1 ポジションのみ。新規シグナルは既存ポジションがあればスキップ

### 同方向連続エントリ抑制

- `InpCooldownBars` 本以内の同方向連打を抑制 (デフォルト 3)
