# バックテスト・プロトコル

## 目的

「過剰最適化された数字」ではなく「フォワードで再現する可能性のある成績」を測ること。
カーブフィッティングを避けるため、ウォークフォワードとアウトオブサンプルを徹底する。

## 期間設計 (XAUUSD)

| 期間 | 用途 |
|------|------|
| 2018-01-01 〜 2020-12-31 | インサンプル (パラメータ探索用) |
| 2021-01-01 〜 2021-12-31 | バリデーション (採否判断用) |
| 2022-01-01 〜 2024-12-31 | アウトオブサンプル (一切触らない最終評価用) |
| 2025-01-01 〜 現在 | フォワード (デモ口座運用で確認) |

**禁止事項**: アウトオブサンプル期間でパラメータを「気持ち寄せる」操作。1度でも触ったら期間を分割し直す。

## モデリング設定

```
Modeling: Every tick based on real ticks (必須)
Initial deposit: 10,000 USD
Leverage: 1:100
Spread: Current (またはブローカーの平均値を固定)
```

**注意**: Modeling=Open prices only や 1 minute OHLC は EMA タッチ系では結果が大きくズレる。必ず real ticks で。

## 評価指標 (採否判断)

下記すべてを満たした場合のみ「採用候補」とする。1つでも満たさなければ不採用。

| 指標 | しきい値 |
|------|---------|
| Net Profit (アウトオブサンプル) | > 0 |
| Profit Factor | ≥ 1.3 |
| Max Drawdown | ≤ 20% |
| 取引数 | ≥ 50 |
| Sharpe Ratio | ≥ 0.7 |
| 最長連敗 | ≤ 8 |
| ベンチマーク超過 | Buy & Hold より Calmar (リターン/MaxDD) で勝つ |

## ベンチマーク

各戦略の結果は以下と並べて比較する:

1. **Buy & Hold ゴールド** (同期間で買い保有しただけの収益)
2. **ランダムエントリ + 同じリスク管理** (シグナルだけランダム化、SL/TPは同じ)
3. **Donchian ブレイクアウト** (`DONCHIAN_BREAK` モード) — 古典の最低ライン

ランダムに勝てない戦略はエッジなしと判断する。

## 手順

### 1. インサンプルでパラメータ探索

```
Optimization: enabled
Forward: disabled
期間: 2018-01-01 ~ 2020-12-31
最適化対象: InpATR_SL_Mult (1.0〜3.0, ステップ 0.25), InpRR (1.0〜3.0, ステップ 0.25), InpEMA_Trend (50〜200, ステップ 25)
```

最適化結果から **Profit Factor 上位10件** を抽出。Net Profit 単体での選定は禁止 (尾根の上の1点を引きやすい)。

### 2. バリデーションで篩い分け

上位10件を 2021 年データで個別に走らせ、評価指標を満たすものだけ残す。
ここで全滅したら戦略自体が筋悪 → 棄却。

### 3. アウトオブサンプルで最終確認

残ったパラメータセットを **触らずに** 2022-2024 で走らせる。
評価指標を満たせば「採用候補」。レポートを `tests/results/{strategy}_{YYYYMMDD}.htm` に保存。

### 4. フォワード (デモ口座)

採用候補をデモ口座で 30〜90 日運用し、バックテストの収益曲線と乖離していないか確認する。
顕著に乖離 (例: バックテストの月次平均利益の 2σ を下回る) したら不採用。

## レポートに記載すべきこと

各 `.htm` レポートと並べて、Markdown で以下を記録:

```markdown
## {strategy_id} - {YYYY-MM-DD}

- 期間: 2022-01-01 ~ 2024-12-31 (out-of-sample)
- ブローカー: {名称}, スプレッド設定: {Current/Fixed}
- パラメータ: InpATR_SL_Mult=1.5, InpRR=1.5, ...
- Net Profit: ...
- Max DD: ...
- Profit Factor: ...
- Sharpe: ...
- 取引数: ...
- 採否: 採用候補 / 不採用
- 不採用の場合の理由: ...
```

## やってはいけないこと

- アウトオブサンプル期間でパラメータを試行錯誤する (= データスヌーピング)
- 過去の良かった月だけを切り出して報告する
- `Modeling: Open prices only` で結果を公表する (タッチ系で偽陽性多発)
- 取引手数料・スプレッドを 0 にして見栄えを良くする
- スプレッドを実態より小さく固定して見栄えを良くする
- ロット数を上げて Net Profit を盛る (リスク調整後リターンを比較すべき)
- 「総じて悪かったが直近半年は良い」を採用根拠にする (生存バイアス)
