# 再編集ルール (repurpose.md)

既存資産 (X / note / LINE 配信) を Threads 用に転用する具体ルール。
週投稿数 14〜28 を実現するための **量産エンジン**。

> **大原則**: 「コピペ転載」は絶対NG。プラットフォームごとに語感・展開を最適化する。

---

## 1. X 投稿 → Threads (140字 → 400字)

### なぜ必要か

X (140字) は「結論勝負」、Threads (500字以内) は「結論 + 体験 + 共感」が刺さる。
そのまま転載するとThreadsでは「物足りない」「煽り気味」に見える。

### 基本ルール

| X 原文の構造 | Threads 拡張ルール |
|---|---|
| 1行目: 結論 | 1行目: 結論 (そのまま) |
| 2行目以降: 補足 | 2行目以降: **体験ストーリー + 数字 + 感情** を肉付け |
| (なし) | 末尾に「あなたはどう?」型の問いかけ or 緩衝句を追加 |

### Step-by-Step 変換手順

#### Step 1: X 原文の構造分解

X 原文をそのまま Claude に投げず、まず以下を抽出する:

- 結論 (1〜2行)
- 主張の根拠 (数字・体験)
- 対象読者 (= ペルソナ A/B/C)

#### Step 2: 体験を肉付け

X では言わなかった以下を追加:

- そのとき自分が何を感じたか (1〜2行)
- 周辺の数字 (X では省略してた具体値)
- Before / After (X では結論しか書かなかった対比)

#### Step 3: 改行・空行で読みやすく

Threads は **改行と空行が命**。X の連続文をそのまま貼ると読まれない。

- 1〜2文ごとに改行
- 段落ごとに空行
- 見出しっぽい行は短く強調

#### Step 4: 末尾追加

- 共感 / 関係構築柱の場合: 「あなたはどう?」型の問いかけ
- 情報提供柱の場合: 「保存しておくと便利」誘導
- 収益化柱の場合: `#PR` 確認 + 緩衝句 (「投資にはリスクがあります」等)

### 変換例

#### X 原文 (130字)

```
給料日に「先取り3万円」を別口座に設定するだけで、家計簿アプリ3回挫折した私が1年で40万貯まった。意志力じゃなくて仕組み。家計簿で日々の支出と戦うより、入口で動かすほうが楽でした。
```

#### Threads 変換後 (約230字)

```
入社2年目の私の貯金、
給料日に残ってた「8,372円」だった。

毎月「今月こそ貯める」って言って、
給料日に欲しい服を買って、
スタバ行って、飲み会行って、
気づいたら通帳が空。

家計簿アプリも3回挫折した。
「自分は意志が弱いんだ」と思ってた。

転機は、給料日に「先取り3万」を別口座に動かす設定をしただけ。
意志力じゃなくて、仕組みに頼った瞬間に、
1年で40万貯まった。

意志が弱いんじゃなくて、
仕組みがなかっただけ。
```

### Threads スレッド機能の活用

X で連投ツイート (5本〜) になるテーマは、Threads では **1スレッドにまとめる** のが推奨。

```
[投稿1: フック + 1要点目]
↓ (スレッド返信)
[投稿2: 2要点目]
↓
[投稿3: 3要点目]
↓
[投稿4: まとめ + CTA]
```

### 変換 NG パターン

- そのまま140字をペースト (薄く見える)
- 絵文字を増やしすぎる (うざく見える)
- ハッシュタグだけ Threads 流に変えて中身は X のまま (=コピペ転載)

## 2. note 記事 → Threads (1記事 → 10〜20投稿)

### なぜ必要か

note の長文 (3,000〜10,000字) は Threads では1投稿に収まらない。
**見出しを抽出して10〜20投稿に分解** することで、note 1本から2〜3週間分の Threads 投稿を生成できる。

### 基本ルール

| note 構造 | Threads 投稿への分解 |
|---|---|
| 章タイトル | 各章を独立した1投稿に |
| 節タイトル | 各節を独立した1投稿に (細かい場合) |
| 結論部 | 「note 本文 への誘導投稿」に |
| まとめ | スレッドの最終投稿 |

### Step-by-Step 変換手順

#### Step 1: note 記事の構造抽出

note を読み、以下を整理:

- 章タイトル一覧 (例: 5章構成 → 5つの主題)
- 各章の核心メッセージ (1行で)
- 数字・データ (Threads でフックに使える)
- ストーリー (Threads でストーリー柱に使える)

#### Step 2: 1記事 → 10〜20投稿の設計

10投稿の場合の例 (老後資金を語る note 記事):

| 投稿# | 内容 | 柱 |
|---|---|---|
| 1 | フック投稿: 「2,000万円問題は既婚前提」 | 情報 |
| 2 | 独身ver の必要額 (2,800万円) の計算 | 情報 |
| 3 | 私が老後資金を意識し始めたきっかけ | 共感 |
| 4 | NISA を月3万で始めた手順 | 情報 |
| 5 | iDeCo 月5,000円の節税効果 | 情報 |
| 6 | 1年経過の数字を晒す | Case Study |
| 7 | やめた支出 5選 | List |
| 8 | 質問投稿: 「老後不安、ある人?」 | 関係構築 |
| 9 | 紹介: 楽天証券で開設した話 (#PR) | 収益化 |
| 10 | 全体まとめ + note への誘導 | 情報 |

#### Step 3: 各投稿を 500字以内に圧縮

note の文章をそのまま 500字に切るのではなく、**各投稿で「1つの主張 + 1つの根拠 + 1つの呼びかけ」** に再構成する。

#### Step 4: スレッド設計

10投稿のうち、関連が深い 3〜5投稿は **スレッド連投** にする。
独立性が高い投稿は **別日に単発投稿** にする。

#### Step 5: note 本文への誘導

最終投稿には:

```
詳細は note 記事「○○」にまとめました。
プロフのリンクから読めます ✏
```

### 変換時の注意

- note の有料記事内容は **無料部分しか転用しない** (有料コンテンツの Threads 転用は購読価値を損なう)
- note の文体 (です・ます調) と Threads (短文・体言止めOK) は違う、必ず書き直す

## 3. LINE 配信 → Threads (一部開示型)

### なぜ必要か

LINE 配信は登録者しか見られない情報。これを Threads で **「予告編」「無料部分」** として開示し、続きを LINE 登録誘導することで MOFU が強化される。

### 基本ルール

| LINE 配信内容 | Threads 投稿への変換 |
|---|---|
| ステップ#1 (お礼+特典) | 「特典を配信中です」誘導投稿 |
| ステップ#2 (失敗ストーリー) | 失敗の冒頭3割を Threads で開示 |
| ステップ#3-4 (教育) | 教育の冒頭1要点を Threads で開示 |
| ステップ#5-7 (案件紹介) | Threads には載せない (LINE 限定価値を保つ) |

### 「予告編型」変換テンプレ

```
[Threads 投稿]

LINE で配信してる7日間ステップの3日目に書いてる話、
ちょっとだけ Threads で先出しします。

「NISA で最初に買うべきは1本だけ」

理由は3つあるんですが、
今日はそのうち1つだけ。

①迷ってる時間が一番もったいないから

完璧な銘柄を3ヶ月かけて選ぶより、
75点の銘柄で3ヶ月運用するほうが、
複利で結果出ます。

残り2つの理由 + 具体的な銘柄名は
LINE のステップ配信で。
プロフのリンクから登録できます ✏
```

### LINE→Threads 変換時の注意

- LINE 限定価値を **絶対に薄めない** (登録メリットがなくなる)
- ステップ#5-7 の「案件紹介本文」を Threads にコピペするのは NG
- Threads では「予告編」までに留め、本編は LINE 内で提供

## 4. 転用優先順位 (時間がない週の判断基準)

### 高優先 (毎週やる)

- X → Threads (X はリアルタイム性が高く、新鮮なネタが多い)
- 過去 note 記事 → Threads (note の SEO 効果も高まる)

### 中優先 (月1〜2回)

- LINE 配信内容 → Threads 予告編型
- 過去 X バズ投稿 → Threads でリブースト

### 低優先 (やらなくてもよい)

- インスタ投稿 → Threads (画像メインなので相性悪い)
- YouTube 動画 → Threads (テキストへの再構成コスト高)

## 5. 自動化のコツ

### Step 1: 月初に「資産棚卸し」を1時間

毎月1日に以下をリストアップ:

- 先月公開した X 投稿 (上位10) → Threads 拡張候補
- 先月公開した note 記事 → 分解候補
- 配信済み LINE ステップ → 予告編候補

### Step 2: Notion / Google Sheets で管理

| 元コンテンツ | プラットフォーム | Threads 化予定 | 担当週 | ステータス |
|---|---|---|---|---|
| 「給料日3,247円ネタ」 | X | story-before-after | 第1週 | 公開済 |
| 「老後資金 2,800万」 | note | 10投稿に分解 | 第2-3週 | 進行中 |

### Step 3: Claude generate-post.md に投げて量産

棚卸しした素材を `automation/generate-post.md` の入力 JSON に変換して連続生成。
週末に翌週分7投稿をまとめて生成 → 投稿予約。

---

## 6. 転用 NG リスト

- X / note / LINE のコピペそのまま投稿 (ペナルティリスク・読者離れ)
- 他人のコンテンツを参考にして書き換えただけのもの (盗用)
- LINE 配信の有料情報・限定情報を Threads で開示 (登録価値毀損)
- 過去の自分の投稿を **同じ週に2回出す** (アルゴリズム警戒対象)

---

## 7. 月次レビュー

毎月末に以下を確認:

- X 由来 / note 由来 / LINE 由来 / オリジナル の比率
- 各由来の平均インプレッション
- どの由来が最も保存・コメントされたか
- 翌月の比率調整
